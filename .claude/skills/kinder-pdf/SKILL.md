# 유치원 PDF 정리

가정통신문 PDF 를 읽어서 **일정 / 제출·준비물 / 식단** 세 가지로 나눠 노션에 넣는다.

## 이 스킬이 존재하는 이유

유치원 알림 서비스(e알리미)는 **"공지가 왔다"** 를 알려준다.
이 스킬이 만드는 것은 **"지금 뭘 해야 한다"** 다.

놓치는 사고는 공지가 온 날에 나지 않는다. 공지는 3주 전에 오고, 그때는 읽고 넘어간다.
문제는 그 3주 뒤인데 그날은 아무도 말해주지 않는다.

그래서 **본문 문장 속에 묻힌 마감을 잡아내는 것이 이 작업의 핵심**이다.
표에 정리된 일정은 누구나 본다. `○일까지 보내주세요` 가 문단 중간에 한 줄 있는 것이 위험하다.

## 0단계 — 설정 확인

```bash
cat apps/kinder-schedule/config.json
```

없으면 `config.example.json` 을 복사해서 만들도록 안내한다. 여기서 읽는 것:

| 값 | 쓰는 곳 |
|---|---|
| `반` | 다른 반 일정을 걸러내는 기준 |
| `방과후과정반` | 방학 때 휴가가 실제로 필요한지 판단 |
| `보호자` | 담당 선택지 |

## 1단계 — PDF 읽기

`inbox/` 의 PDF 를 **Read 도구로 직접 읽는다.** Read 가 PDF 를 지원하므로 별도 API 키가 필요 없다.

**전부 읽는다. 요약하지 않는다.** 표만 보고 본문을 건너뛰면 마감을 놓친다.

## 2단계 — 세 가지로 나누기

### ① 유치원 일정 — 행사·휴원

날짜가 있고 "그날 무슨 일이 일어나는" 것.

| 종류 | 예 |
|---|---|
| 행사 | 운동회, 발표회, Cooking Day, 졸업사진 촬영 |
| 휴원 | 방학, 재량휴업일, 개원기념일 |
| 단축수업 | 방학식 당일 조기 하원 등 |
| 상담 | 학부모상담 기간 |
| 기타 | 방역, 개학일, 정상수업 안내 |

### ② 제출·준비물 — 마감이 있는 할 일

**부모가 뭔가 해야 하는** 것. 이게 가장 놓치기 쉽다.

| 종류 | 예 |
|---|---|
| 서류 | 동의서, 신청서, 조회동의서 |
| 준비물 | 여벌옷, 양말, 도시락 |
| 납부 | 원비, 현장학습비 |
| 신청 | 상담 일정 예약, 방과후 신청 |

마감일이 본문에 안 적혀 있으면 `마감일` 을 비워두고 메모에 `(상시)` 또는 원문을 적는다.
**마감이 불명확하다고 버리지 않는다.** 버리면 그게 곧 놓치는 것이다.

### ③ 급식 식단

날짜별 점심·간식. 식단표 PDF 에서만 나온다.

## 3단계 — 우리 반만 남기기

통신문에는 **여러 반의 일정이 섞여 나온다.** 반이 명시된 항목은 `config.반` 과 대조해서 해당하는 것만 남긴다.

예시 — 아이가 `창의로운 어린이반` 일 때:

```
7/7(화) 과일빙수  | 창의로운, 씩씩한   → 남긴다
7/8(수) 수박화채  | 명랑한, 다정한     → 버린다
7/9(목) 과일샐러드 | 착한, 예쁜        → 버린다
```

반 표시가 없으면 전체 대상으로 보고 남긴다.
**버린 항목은 마지막에 몇 건 걸렀는지 알려준다.** 조용히 버리면 잘못 걸러도 모른다.

## 4단계 — 휴가필요 판단

| 상황 | 휴가필요 |
|---|---|
| 휴원·방학 (교육과정반 미운영) | ✅ |
| 방과후과정반 휴원 기간 | `config.방과후과정반` 이 true 일 때만 ✅ |
| 평일에 부모가 참석하는 행사 (운동회·상담·졸업식) | ✅ |
| 주말·공휴일 행사 | ❌ |
| 정상수업일, 유치원 내부 일정(방역 등) | ❌ |

**방과후 여부로 결과가 크게 갈린다.** 예를 들어 여름방학이 7/23~8/11 이어도, 방과후를 다니면 실제 공백은 7/23~7/31 뿐이고 8/3 부터는 등원한다. 이때는 두 건으로 나눠서 넣는다.

담당은 기본 `미정` 으로 둔다. 정하는 건 부부가 할 일이다.

## 5단계 — 중복 걸러내기 (가장 중요)

통신문에는 `주요 학사일정을 다시 안내해 드립니다` 같은 표가 **매번 반복해서 실린다.**
그대로 넣으면 몇 주 만에 같은 일정이 5개씩 쌓여 노션이 못 쓰게 된다.

저장 **전에** 기존 항목을 읽어서 대조한다:

```bash
S=.claude/skills/notion-organizer/scripts/notion.py
python3 $S query --data-source <일정_ds_id>
python3 $S query --data-source <제출_ds_id>
```

판단 기준:

- **날짜가 같고** 제목의 핵심 낱말이 겹치면 중복으로 본다
  (`재량휴업일` / `재량 휴업일(개원기념일)` → 같은 것)
- 식단은 날짜 하나에 한 행이므로 날짜만 같으면 중복이다
- 애매하면 **버리지 말고** 사용자에게 "이거 기존 것과 같은 건가요?" 하고 묻는다

기존 항목의 내용이 더 자세해졌으면(날짜가 확정됐다든지) 새로 넣지 말고 **기존 행을 고친다.**

## 6단계 — 확인받기

노션에 만들기 **전에** 표로 보여준다. 만들어진 뒤 고치는 것보다 훨씬 싸다.

```
📅 유치원 일정 (창의로운 어린이반)

| 일정명 | 날짜 | 종류 | 휴가 |
|--------|------|------|------|
| 여름방학 | 7/23~8/11 | 휴원 | ⚠️ |
| 재량휴업일(개원기념일) | 10/2(금) | 휴원 | ⚠️ |

📄 제출·준비물

| 항목명 | 마감 | 종류 |
|--------|------|------|
| 2학기 상담 일정 예약 | 10/20 전 | 신청 |

제외: 다른 반 일정 2건 (7/8 명랑한·다정한, 7/9 착한·예쁜)
중복: 기존과 같아 건너뜀 3건

이대로 넣을까요?
```

## 7단계 — 반드시 물어봐야 할 것

아래는 **추측하지 말고 묻는다.** 틀리면 실제로 문제가 생기는 것들이다.

- **날짜가 문서 안에서 어긋날 때** — 제목은 `7/4(토)` 인데 본문은 `7/14(토)` 인 경우가 실제로 있었다. 요일을 계산해서 어느 쪽이 맞는지 짚어주고 확인받는다
- **휴원인지 단축수업인지 애매할 때** — 휴가를 내야 하는지가 갈린다
- **마감일이 "이번 주까지" 처럼 상대적일 때** — 통신문 발행일 기준으로 계산한 뒤 확인받는다
- **우리 반 해당 여부가 불명확할 때**

## 8단계 — 노션에 넣기

`notion_targets.json` 에서 `data_source_id` 를 읽어 저장한다.

```bash
python3 .claude/skills/notion-organizer/scripts/notion.py \
  add-rows --data-source <ds_id> --rows /tmp/.../rows.json
```

- `출처` 에 `2026-07-03 가정통신문` 처럼 어느 PDF 에서 왔는지 남긴다. 나중에 원본을 찾아갈 수 있어야 한다
- JSON 은 스크래치패드에 쓴다. 사용자 프로젝트를 더럽히지 않는다
- 다 끝나면 처리한 PDF 를 `inbox/done/` 으로 옮긴다

## 자주 하는 실수

- **표만 읽고 본문을 건너뛴다** → 문장 속 마감을 놓친다. 이게 가장 큰 실패다
- **다른 반 일정을 그대로 넣는다** → 무관한 항목이 3분의 2가 되어 정작 볼 것이 안 보인다
- **중복 검사를 건너뛴다** → 학사일정 표가 매주 반복 등장해 몇 주 만에 쓸 수 없게 된다
- **마감일이 불명확하다고 버린다** → 버린 것이 곧 놓친 것이다. 비워두고 메모에 원문을 남긴다
- **애매한 걸 추측으로 채운다** → 휴원/단축을 잘못 넣으면 휴가를 잘못 낸다
