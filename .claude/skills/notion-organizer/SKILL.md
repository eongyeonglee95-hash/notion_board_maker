# 노션 정리 에이전트

정리되지 않은 내용을 받아서, 노션에 **다시 찾아볼 수 있는 구조**로 만든다.

## 가장 중요한 원칙

사용자는 정리를 어려워한다. 그래서 **사용자에게 구조를 묻지 않는다.**
내용을 읽고 구조를 제안하고, 확인만 받는다.

"어떻게 정리할까요?" (X)
"이렇게 정리하겠습니다. 이대로 진행할까요?" (O)

## 정리의 3원칙

### 1. 폴더를 파지 말고 속성을 붙인다
정리를 못하는 가장 큰 이유는 페이지 안에 페이지를 계속 만들기 때문이다.
찾으려면 어디 넣었는지 기억해야 한다.

**대신 데이터베이스 1개 + 속성으로 분류한다.** 속성은 나중에 필터·정렬로 조합할 수 있다.

```
[나쁨]  AI도구 / 코딩 / CLI / Claude Code / 사용법.md
[좋음]  DB "AI 개발도구"
        Claude Code | 카테고리:코딩 | 형태:CLI | 숙련도:익힘
```

### 2. 한 항목 = 한 행
"Claude Code 사용법"과 "Cursor 사용법"이 한 페이지에 섞여 있으면 안 된다.
각각이 행이 되고, 상세 내용은 그 행의 페이지 본문에 들어간다.

### 3. 속성은 5~7개까지만
많으면 채우다 지쳐서 안 쓰게 된다. 반드시 넣을 것:
- **이름** (title) — 필수
- **분류** (select) — 큰 카테고리 하나
- **태그** (multi_select) — 여러 개 붙는 것
- **상태** (status 또는 select) — 진행/숙련 정도
- **날짜** (date) — 언제 것인지

## 작업 순서

### 0단계 — 사전 확인 (매번)

```bash
python3 .claude/skills/notion-organizer/scripts/notion.py whoami
```

실패하면 `references/setup.md` 를 보고 토큰 설정을 안내한다.

부모 페이지 ID를 모르면:
```bash
python3 .claude/skills/notion-organizer/scripts/notion.py search --type page
```

### 1단계 — 원본 읽기

파일이면 Read, 붙여넣은 텍스트면 그대로. 링크가 섞여 있으면 살린다.
**원본을 요약하지 말고 전부 읽는다.** 항목이 몇 개인지 세는 것이 핵심이다.

### 2단계 — 분석 (서브에이전트)

항목이 **15개 이상**이거나 원본이 여러 파일에 흩어져 있으면
`content-analyzer` 서브에이전트에게 분석을 맡긴다. 적으면 직접 한다.

분석에서 뽑아야 할 것:
- 항목 목록 (중복 제거, 같은 것 다르게 부른 것 통합)
- 항목들이 공통으로 가진 성질 → 속성 후보
- 빠져 있는 정보 (예: 어떤 도구는 설치법이 없음)

### 3단계 — 스키마 설계 (서브에이전트)

속성 구성이 애매하면 `schema-designer` 서브에이전트를 쓴다.
`references/schema-patterns.md` 에 정리 유형별 검증된 스키마가 있다.

색상 배정과 표 미관은 `references/formatting.md` 를 따른다.

### 4단계 — 확인받기

생성 전에 **표 형태로** 미리 보여준다. 노션에 만들어진 뒤 고치는 것보다 훨씬 싸다.

```
DB 이름: AI 개발도구  🛠️

| 도구명 | 카테고리 | 형태 | 숙련도 | 링크 |
|--------|----------|------|--------|------|
| Claude Code | 코딩 | CLI | 익힘 | ... |
| Cursor | 코딩 | IDE | 써봄 | ... |

행 24개, 속성 5개. 이대로 만들까요?
```

### 5단계 — 생성

```bash
# DB 생성 → data_source_id 를 받는다
python3 .../notion.py create-db --parent-page <page_id> --spec /tmp/.../spec.json

# 받은 data_source_id 로 행 추가
python3 .../notion.py add-rows --data-source <ds_id> --rows /tmp/.../rows.json
```

JSON 파일은 스크래치패드 디렉토리에 쓴다. 사용자 프로젝트를 더럽히지 않는다.

행이 30개를 넘으면 나눠서 넣고, 중간에 실패해도 어디까지 됐는지 보고한다.

### 6단계 — 결과 전달

노션 URL을 주고, **어떻게 쓰면 되는지** 한두 줄 덧붙인다.
추천 뷰(보드/캘린더/갤러리)가 있으면 만드는 법을 알려준다.
(뷰 생성은 API로 안 되므로 클릭 순서를 안내한다.)

## API 주의사항 (2025-09-03 버전)

노션 API가 최근에 바뀌었다. 예전 방식으로 호출하면 **전부 실패한다.**

| 작업 | 바뀐 점 |
|------|---------|
| DB 생성 | 속성은 `initial_data_source.properties` 아래 |
| 행 추가 | `parent` 는 `data_source_id` (구: `database_id`) |
| 관계 속성 | `relation.data_source_id` 만 사용 |

상세는 `references/notion-api.md`.

## 자주 하는 실수

- **정적 표(table 블록)를 쓴다** → 필터도 정렬도 안 된다. 반복되는 항목은 무조건 DB.
- **속성을 15개 만든다** → 사용자가 안 채운다. 5~7개.
- **본문에 다 때려넣는다** → 행의 속성으로 뽑아낼 수 있는 건 속성으로.
- **부모 페이지에 통합 연결을 안 했다** → `object_not_found` 가 뜬다. 노션에서 ··· > 연결.
