# 표와 페이지를 보기 좋게 만드는 규칙

노션이 예뻐 보이는 건 감각이 아니라 **일관성**이다.
같은 의미에 같은 색을 쓰고, 순서를 지키면 정돈되어 보인다.

---

## 색 배정 규칙

노션 색: `default` `gray` `brown` `orange` `yellow` `green` `blue` `purple` `pink` `red`

### 진행 상태 — 회색에서 초록으로 흐르게
```
안함/대기    gray     ← 시작 안 함은 항상 회색
진행중       yellow   ← 진행은 노랑
검토/보류    orange
완료         green    ← 끝난 것은 항상 초록
문제/취소    red
```

### 숙련도·이해도 — 낮음에서 높음으로
```
모름/안써봄   gray
써봄/애매     yellow
익힘/이해함   green
주력/설명가능 blue     ← 최상위는 파랑
```

### 우선순위 — 뜨거운 색이 급한 것
```
긴급  red  →  높음  orange  →  보통  yellow  →  낮음  gray
```

### 카테고리 — 의미로 묶기
```
코딩·개발    blue
문서·글쓰기  green
디자인·이미지 purple
리서치·검색  orange
자동화·기타  gray
비용·유료    red      ← 돈 나가는 건 빨강으로 눈에 띄게
무료         green
```

**절대 규칙 3가지**
1. 한 DB 안에서 같은 의미에는 반드시 같은 색.
2. `red` 는 아껴 쓴다. 다 빨강이면 아무것도 안 급해 보인다.
3. `default` 는 쓰지 않는다. 색이 없으면 안 정한 것처럼 보인다.

## 속성 순서

노션 표는 왼쪽부터 읽힌다. 중요한 순서로 배치한다.

```
1. 이름 (title)        ← 무엇인가
2. 상태 / 숙련도       ← 지금 어떤가
3. 분류 (select)       ← 어디에 속하나
4. 태그 (multi_select) ← 부가 분류
5. 날짜                ← 언제
6. 링크 (url)          ← 어디로
7. 메모 (rich_text)    ← 긴 것은 맨 뒤
```

긴 텍스트를 앞에 두면 표가 지저분해진다. **rich_text 는 항상 오른쪽 끝.**

## 아이콘

- **DB 아이콘**: 주제를 나타내는 이모지 하나. 🛠️ 📚 💡 ✅ 📅
- **행 아이콘**: 분류를 한눈에 구분할 수 있을 때만 붙인다.
  전부 같은 이모지면 안 붙이느니만 못하다.
  ```
  코딩 도구 🤖 / 문서 도구 📝 / 이미지 도구 🎨
  ```
- 이모지는 **행마다 다른 의미**를 가질 때 가치가 있다.

## 페이지 본문 구조

```
💡 콜아웃 (blue_background)   ← 한 줄 요약. 맨 위에 하나.
─────────                      ← divider
## 소제목                      ← heading_2 부터 시작 (heading_1 은 제목과 중복)
   본문 / 불릿 / 코드
─────────
## 다음 소제목
```

**규칙**
- 페이지 맨 위에 **한 줄 요약 콜아웃**. 나중에 열었을 때 3초 안에 파악된다.
- `heading_1` 은 쓰지 않는다. 페이지 제목이 이미 h1이다.
- 섹션 사이에 `divider`. 스크롤할 때 경계가 생긴다.
- 코드는 반드시 `code` 블록에 `language` 를 지정한다. 색이 입혀진다.
- 접어둘 상세 내용은 `toggle`. 페이지가 길어지면 읽지 않게 된다.

### 콜아웃 색 용도
```
blue_background    요약, 정보
yellow_background  주의, 팁
red_background     경고, 하지 말 것
green_background   결론, 결정사항
gray_background    참고, 부연
```

## 정적 표를 쓸 때

**반복되는 항목은 표가 아니라 DB로.** 표는 문서 안의 작은 비교용으로만.

좋은 예: 명령어 옵션 표, 단축키 표, 비교표(3~8행)
나쁜 예: 도구 20개 목록 → 이건 DB

표 만들 때:
- 열은 **2~4개**. 5개 넘으면 좁아서 못 읽는다.
- 첫 열은 짧은 키워드(명령어, 옵션명).
- `has_column_header: true` 를 켠다.
- 셀 안 텍스트는 **한 줄로**. 길면 DB로 옮길 신호다.

## 흔한 실수

| 실수 | 결과 | 대신 |
|---|---|---|
| 색을 안 정하고 자동 배정 | 무지개색, 의미 없음 | 스키마에 옵션+색 미리 정의 |
| 속성 12개 | 빈 칸 투성이 | 5~7개로 줄이기 |
| 메모 열이 두 번째 | 표가 글자로 뒤덮임 | 맨 오른쪽으로 |
| 모든 행에 같은 이모지 | 시각적 구분 0 | 분류별로 다르게, 아니면 생략 |
| 페이지에 h1 남발 | 제목 계층 붕괴 | h2 부터 |
| 20행짜리 정적 표 | 필터·정렬 불가 | DB로 전환 |
