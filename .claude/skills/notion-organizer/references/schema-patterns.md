# 정리 유형별 데이터베이스 스키마

바로 쓸 수 있는 검증된 스키마 모음. 그대로 쓰지 말고 **원본 내용에 맞춰 속성을 빼고 더한다.**
없는 정보를 위한 속성은 만들지 않는다. 빈 칸만 늘어난다.

---

## 1. 도구·서비스 사용법 (AI 개발도구, 라이브러리, SaaS)

가장 흔한 케이스. "써봤는데 어떻게 쓰는지 까먹는" 문제를 푼다.

| 속성 | 타입 | 옵션 / 설명 |
|---|---|---|
| 도구명 | title | |
| 카테고리 | select | 코딩 `blue` / 문서·글쓰기 `green` / 이미지·영상 `purple` / 검색·리서치 `orange` / 자동화 `yellow` / 기타 `gray` |
| 형태 | select | CLI `brown` / 웹 `blue` / IDE확장 `purple` / 데스크탑앱 `pink` / API `gray` |
| 숙련도 | select | 안써봄 `gray` / 써봄 `yellow` / 익힘 `green` / 주력 `red` |
| 비용 | select | 무료 `green` / 부분유료 `yellow` / 유료 `red` |
| 링크 | url | 공식 문서 |
| 한줄요약 | rich_text | 이게 뭐 하는 건지 한 문장 |
| 추가일 | date | |

**본문 구조** (각 행 안에 들어갈 내용):
```
💡 콜아웃 — 한 줄 요약
## 설치
   code 블록
## 기본 사용법
   code 블록 + 설명
## 자주 쓰는 명령어
   정적 표 (명령어 | 설명)
## 막혔던 것 / 팁
   불릿
## 참고 링크
```

**추천 뷰**: 카테고리별 보드 → 숙련도 필터로 "안써봄"만 보면 학습 대기열이 된다.

## 5. 아이디어·메모 (인박스)

속성을 최소로. 적는 순간 마찰이 있으면 안 적게 된다.

| 속성 | 타입 | 옵션 |
|---|---|---|
| 내용 | title | 한 줄로 |
| 종류 | select | 아이디어 `yellow` / 할일 `blue` / 링크 `green` / 그냥메모 `gray` |
| 처리 | select | 미처리 `red` / 살릴것 `green` / 보류 `gray` / 버림 `brown` |
| 적은날 | date | |

**핵심**: 여기는 임시 보관소다. 주기적으로 "살릴것"을 제대로 된 DB로 옮긴다.

## 스키마를 직접 설계할 때

1. **원본에서 반복되는 항목을 찾는다.** 3번 이상 나오는 성질이 속성 후보다.
2. **값의 종류가 정해져 있으면** `select`, **여러 개 붙으면** `multi_select`, **자유 서술이면** `rich_text`.
3. **`select` 옵션이 10개를 넘으면** 분류가 잘못된 것이다. 상위 개념으로 묶는다.
4. **"기타"는 최후에만.** 절반이 기타면 분류 기준이 틀린 것이다.
5. **시간 정보가 있으면 무조건 `date` 를 넣는다.** 나중에 정렬·캘린더로 살아난다.
6. **title 은 검색해서 찾을 이름으로.** "메모1" 같은 건 최악이다.
